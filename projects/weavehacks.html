ReviveAgent

An agent that brings dead repositories back to life

Oct 2025 · Weavehacks 2 · Weights & Biases × Google Cloud · SF Hack Week
Best Self-Improving Agent · 67 teams
Generative & foundation models Hackathons

The problem

The reference implementation for a method you want to build on is four years old, its dependencies no longer resolve, and the APIs it calls have moved underneath it. Reproducing the original result is mostly archaeology, and it is the single most common reason a good idea never gets built on. It is also badly suited to a one-shot code model: you cannot tell whether a fix worked without running the thing.

What I built

  • An agent that takes a repository URL, diagnoses why it no longer runs (unresolvable dependencies, moved or deleted APIs, changed environment assumptions), and iterates on fixes.
  • A self-improving loop: the agent runs its own attempts, reads what broke, and revises, rather than emitting one patch and stopping. That loop is what the category award was for.
  • Demonstrated on a reinforcement learning environment repository roughly four years stale, brought back up and compared against a current RL environment.
Best Self-Improving Agent
Category award among 67 teams at Weavehacks 2, run by Weights & Biases and Google Cloud during SF Hack Week.

What worked

  • Bit rot comes with a free reward function. The code either imports and executes or it does not, so the agent can score its own attempts without a human in the loop, which is exactly the condition a self-improving loop needs.
  • Scoping to revival rather than general repair. The target behavior already exists and is described in the repository, so the agent has a specification to work toward instead of having to infer intent.

What didn't

  • One repository, one weekend. There is no measurement across the range of decay that actually occurs: an unpinned dependency, a deleted API and a missing dataset are very different failures with very different fix rates.
  • The loop verifies that the code runs, not that it reproduces the original numbers. For research repositories that is the harder and more useful half of the problem, and it is untouched.
